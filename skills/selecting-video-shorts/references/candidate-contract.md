# 후보 기록과 검증 기준

## 기록할 정보

기존 파이프라인의 형식을 존중한다. 아래는 필수 정보의 의미이며, 새로운 고정 스키마나
특정 도구에 대한 의존성을 요구하지 않는다. 시간과 원문을 얻을 수 없으면 그 필드를
미확인으로 남기고 탐색 후보로 전달한다.

| 범위 | 기록할 내용 |
|---|---|
| 원자료 | 영상 URL 또는 파일, 회차, 대본 파일과 리비전, 자막·전사의 출처, 실제 검수 상태 |
| 작업 목적 | 정보 전달·인물/채널 발견·예고편의 우선순위, 시청자, 지정 인물·길이·개수, 적용한 가정 |
| 근거 | 출처 URL과 확인일, 무엇을 뒷받침하는지, 사실과 제작 경험의 구분 |
| 후보 | 고유 ID, 주제, 제목과 첫 화면 문구 제안, 목적에 맞는 이유, 편집상 우선순위 |
| 발췌 | 순서가 있는 원본 범위 목록, 시간의 종류와 단위, 토큰·발화 ID, 실제 발췌 대사와 화자 |
| 편집 | 약속한 질문 → 원문에 있는 답과 설명 → 결론, 꼭 남길 문맥과 원문 근거, 피할 해석 |
| 완결성 | 답변 전체와 다음 주제 전환까지 읽은 범위, 선택 구간 뒤에 남은 설명, 그 지점에서 끝내는 이유, 의미 검수 상태 |
| 추가 시청 안내 | 필요할 때만 CTA 문구, 연결 대상과 추가로 얻는 내용. 편 안에서 전달할 답을 본편으로 유보하지 않음 |
| 중복 | 같은 주제의 대안은 원 후보 ID에 연결하고 별도 주제로 합산하지 않음 |
| 상태 | 화자, 음성 컷 경계, 화면 속 인물, 자막 검증을 분리해 기록 |
| 보류 | 보류 이유와 재평가에 필요한 구체적인 자료 또는 확인 |

여러 입력이나 후속 자동 편집에 넘기는 경우 원본 해시와 사용한 교정 내역도 기록하면
원문이 바뀐 뒤 오래된 후보를 잘못 쓰는 것을 막을 수 있다. 실제 계산하지 않은 해시나
검수 결과를 만들지 않는다.

## 시간과 길이

음성 단어 앵커를 쓸 수 있다면 발췌의 첫 단어 시작과 마지막 단어 끝을 기록한다.
자막 표시 시간, ASR 음성 시간, 프레임 확정된 편집 시간은 같은 값으로 취급하지 않는다.
표시 시간만 있다면 해당 범위는 탐색용이며 정밀 컷의 근거가 아니다.

원본 범위 하나의 길이:

```text
source_span_seconds = source_end_seconds - source_start_seconds
```

여러 구간을 연결하는 후보의 선택 범위 합계:

```text
selected_source_span_seconds = sum(source_span_seconds for each selected part)
```

이 합계에는 선택 범위 안의 침묵이 포함된다. 서로 떨어진 범위 사이의 공백은 포함하지
않는다. 로고스팅, 전환, 무음 삭제, 실제 컷 조정이 반영된 최종 MP4 길이와는 별개다.
대본 길이로 추정한 값이라면 앵커에서 계산한 값과 구분한다.

초 단위 원값을 보존한다. 탐색용 분:초 표시는 시작을 내림하고 끝을 올림하는 등 사용한
반올림 규칙을 적는다. 표기된 두 시각의 차이가 원값의 합계와 정확히 같아 보이도록
원값을 바꾸지 않는다. 원본이 한 시간이 넘으면 시간 표기 체계도 명시한다.

다음 상태가 있으면 해당 후보의 컷 검수가 남아 있음을 표시한다.

- 범위 안에 음성 앵커가 없는 단어 또는 화자가 불명확한 발화가 있음
- 두 화자의 단어가 같은 ASR 앵커를 공유하거나 발화가 겹침
- 문장의 시작이나 끝이 잘렸을 가능성이 있음
- 재편집본과 대본의 원본 타임라인이 다름

합계가 계산된다는 이유로 경계를 검증 완료로 바꾸지 않는다. 음성이 없는 단어를
버리거나 자막 표시 시간으로 음성 컷을 연장해 검사를 통과시키지 않는다.

## 전달 전 확인

1. 원문 인용·화자·ID가 채택한 리비전과 일치하고 편집 문구를 실제 발언으로 취급하지
   않았는지 확인한다.
2. 각 범위의 시각·단위·합계를 재계산하고 미확정 시간을 확정된 컷으로 표시하지
   않았는지 확인한다.
3. 제목만 본 처음 시청자가 이 편만으로 약속한 답을 얻는지 확인한다. 관련 답변의 끝과
   다음 주제 전환까지 읽고, 선택 구간 뒤의 핵심 설명을 누락하지 않았는지 기록한다.
   ‘도와줘야 하잖아요’ 같은 종결형도 뒤에서 실제 도움의 방식과 조건을 설명하면
   그 자체로 설명 완결의 근거가 아니다.
4. 필요한 질문·응답·조건을 남겼는지, CTA가 전달한 답을 확장하는지, 같은 주제의
   대안을 중복 집계하지 않았는지 확인한다. 정보형이 너무 길면 질문을 좁히거나 길이
   제약과의 충돌을 밝힌다. 결론을 삭제하거나 출처에 없는 요약을 발언으로 만들지 않는다.
5. 근거 링크와 로컬 참조가 올바르고 자료가 뒷받침하는 강도로 결론을 썼는지 확인한다.

자동 검사 결과가 원문 인용과 계산의 일치를 확인하더라도 청취·화면·발음·자막 품질을
검증한 것은 아니다. 의미 검수가 실패한 편은 자막 검사가 통과해도 발췌 완료로 표시하지
않는다. 에이전트의 원문 의미 검수와 사용자의 청취 검수도 구별해 인계한다.
