# Structural exploration

Read for a new composition, open redesign, or an explicit request for design variety. The result is a small comparison that helps make a design choice, not a compulsory multi-app production process.

## Start from the task

Write a compact constraint list: required information, actions, content, assets, brand decisions, input modes, and quality needs. Label old placements and suggested copy as provisional when they have not been adopted. Keep that list stable while comparing structures.

## Sketch different organizations

For an open brief, two or three inexpensive candidates are usually enough. Follow the user's requested count or budget. A sketch can be a short spatial description, an ASCII wireframe, or a simple visual already supported by the workspace. Polished code and new artwork can wait.

For each candidate, show:

- What receives attention first and how the rest is grouped around it.
- The main action path and how secondary information is reached.
- The spatial relationship that differs from the other candidates.
- How all required information and actions remain available.
- One practical tradeoff for this task and input mode.

Explore differences in hierarchy, inclusion/adjacency, area allocation, density, or interaction/disclosure. A different font or palette on the same arrangement is a style variation, not another structure. If candidates reduce to the same boxes and actions after labels and decoration are removed, merge them and explore a different organization.

Keep useful conventions recognizable. Strange geometry, hidden critical state, invented features, or inaccessible controls do not make a candidate better. Equally, a fixed-layout palette request should receive palette variations rather than an unsolicited structural redesign.

## Choose without freezing the search accidentally

Compare candidates against the same tasks and important states. For a novelty request, also identify the comparison baseline from available previous designs and named references. Show how the final recommendation changes a relevant information relationship or user path and why that helps this task. Preserve any resemblance the user explicitly requested. Mirroring or exchanging regions without a useful change is weak novelty evidence.

Select among viable candidates using task fit and the requested newness together. If none offers a meaningful difference, reconsider within the remaining agreed or stated budget, then report the unmet goal rather than presenting a repeated structure as a novelty success. Missing comparison material is a limitation, not permission to invent differences. Do not loop indefinitely or invent a universal distance threshold.

For one authorized deliverable, choose, label the recommendation, and continue. Ask only when a material preference or missing constraint needs the user's decision. When novelty is not requested, task fit governs; familiar patterns may be the best choice.

Keep the exploration proportional: one shared comparison artifact, not separate projects, worktrees, image sets, or dependency installations for every idea. Reuse supplied assets. Additional research is useful when it provides a missing structural principle; it is not required for every design.

## Check the result and the relay

Review the closest pair of candidates and name their actual structural difference. A concise rationale is enough; self-assigned novelty scores and claimed generation probabilities are not measurements. If the scope includes rendered comparisons, use a common viewport, content, and state so decoration does not masquerade as structure.

The handoff distinguishes required behavior, the recommended or adopted layout, remaining options, and missing validation. A candidate's positions and wording become implementation choices under authorization; they do not become user requirements merely by appearing in the first draft.
