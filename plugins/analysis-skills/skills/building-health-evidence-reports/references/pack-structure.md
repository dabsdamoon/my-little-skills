# 산출물 구조

**어디에 두나.** 작업 중인 저장소가 있으면 그 저장소의 작업 폴더(예: Git 에 넣지 않는 `_workspace/`) 안에 만든다. 저장소 루트나 Git 이 추적하는 폴더에 만들지 않는다. 저장소 밖 작업이면 사용자가 정한 곳에 둔다.

```
<주제>/
  <주제>-리포트.md      전달물 전부. 이것 하나만 봐도 되게
  그래프/                PNG. 발표자료에 바로 삽입 가능
  원문/                  확보한 원본 자료 (PDF 등)
  _작업용/               갱신용 내부 파일. 요청자는 안 봐도 됨
    sources.yaml          기계가 읽는 소스 레지스트리
    확보경로.md            다음에 어디를 어떻게 뚫는지
    미해결과제.md          P1~P3 우선순위
    <원자료 추출본>.csv
    <그래프생성>.html
```

## 파일명 규칙

**리포트 파일명은 폴더 밖으로 나가도 뭔지 알 수 있어야 한다.** 요청자가 이것만 떼어 메일에 붙이거나 바탕화면에 둔다. `리포트.md`가 아니라 `제왕절개율-VBAC-리포트.md`.

폴더명은 한글을 쓴다. 비개발자가 받는 물건이다.

## 왜 한 파일인가

문서를 역할별로 쪼개면:
1. "어느 파일부터 보나" 안내 파일이 필요해진다 — 쪼갰기 때문에 생긴 비용
2. 같은 수치가 여러 파일에 적힌다 — 갱신할 때 하나를 빠뜨리면 서로 다른 숫자를 말하는 문서가 된다

부록은 같은 파일 안의 섹션으로 넣는다. 분리는 **원문·이미지·작업용 파일**에만 적용한다.

## _작업용/ 에 무엇을 남기나

다음에 같은 요청이 왔을 때 처음부터 다시 파지 않기 위한 것. 요청자용 문서에 들어가면 안 되는 내용들이다.

- **확보경로.md** — 어느 URL이 JS 렌더링이라 자동 수집이 안 되는지, 어느 API가 SSO 리다이렉트로 막히는지, 어느 기관이 몇 월에 발표하는지
- **sources.yaml** — id / 기관 / URL / 갱신주기 / 라이선스 / last_checked / status
- **미해결과제.md** — 해결된 것은 취소선으로 남긴다. 뭘 이미 시도했는지가 다음 사람에게 정보다
- **원자료 추출본** — API로 받은 CSV 등. 재현 가능해야 한다

## 갱신 주기

대부분의 국가통계는 **연 1회 공표**다. 실시간 감시는 낭비다. 기관별 발표 월을 `확보경로.md`에 적어두고 그때만 확인한다.
