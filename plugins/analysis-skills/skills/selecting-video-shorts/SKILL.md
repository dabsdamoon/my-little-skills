# Selecting Video Shorts

긴 영상에서 처음 보는 사람도 이해할 수 있는 짧은 대화나 장면을 고르고, **왜 이 구간인지,
어디를 쓸지, 무엇을 함께 남겨야 하는지**를 설명한다. 한 질문의 답이나 한 경험의 변화를
마무리할 수 있는 단위로 발췌한다. 사용자가 원한 목적에 맞춰 정보 전달, 인물 소개,
새 시청자의 발견, 본편 관심 등의 우선순위를 정한다.

## 1. 목적과 원자료를 확인한다

- 대상 영상·회차, 시청자, 목적, 중심 화자와 길이·개수 요청을 기존 맥락에서 확인한다.
  누락된 비필수 조건은 합리적으로 가정하고 표시한다. 특정 채널의 목적을 모든 쇼츠의
  목적으로 일반화하지 않는다.
- 정보 전달, 인물·채널 발견, 예고편 중 무엇이 우선인지 구별한다. 정보 전달이 목적이면
  시청자가 본편을 누르지 않아도 이번 편이 약속한 질문의 답을 얻어야 한다. 조회 유입을
  이유로 답이나 필수 설명을 뒤로 미루지 않는다. 목적이 불명확하면 답을 유보하는
  예고편 편집을 임의로 채택하지 않는다.
- 프로젝트 지침과 기존 대본, 자막, 화자 결정, 검수 상태, 음성 단어 앵커, 영상 파일을
  먼저 찾는다. 업로더 제공 자막, 플랫폼 자동 자막, 별도 ASR 중 대본의 출처를 밝힌다.
- 교정·검수된 최신 자료를 기준으로 삼고 이전 리비전을 보존한다. 사용자 검수 완료,
  자동 분석 결과, 원문 내용의 사실 여부는 서로 다른 상태다.
- 이미 있는 자료로 후보를 고를 수 있으면 재다운로드·재전사·모델 로딩을 반복하지 않는다.
  자료가 불완전해도 가능한 후보를 제시하고, 부족한 부분의 검수를 표시한다.

## 2. 근거를 실제 선정 기준으로 바꾼다

웹 근거를 요청받았거나 플랫폼의 현재 기능·제한을 근거로 삼을 때는
[근거 조사 지침](references/evidence-and-sources.md)을 읽는다. 공식 문서와 학술 원문을
우선하고, 플랫폼의 설명·제작자의 경험·편집자의 판단을 구별한다. 기존 조사 결과를
재사용할 때도 출처와 확인일을 남기고, 변할 수 있는 규칙은 다시 확인한다.

다음 질문으로 후보를 평가한다. 고정 점수나 일률적인 최적 길이를 만들지 않는다.

| 판단 질문 | 대본에서 확인할 것 |
|---|---|
| 첫 순간에 볼 이유가 있는가 | 구체적인 질문, 의외의 비유, 경험의 변화, 시청자와 관련된 문제 |
| 한 편의 중심이 하나인가 | 한 질문과 답, 한 비유와 설명, 한 장면의 감정 변화 |
| 사전 지식 없이 이해되는가 | 인물·대상·상황과 ‘이게’, ‘그때’ 같은 지시어의 대상 |
| 약속한 정보나 감정이 마무리되는가 | 질문에 대한 답과 필요한 설명·조건이 실제로 포함되는지. 문장 종결만으로 설명 완결을 판정하지 않음 |
| 원문의 뜻과 조건이 남는가 | 필요한 전제, 유보, 예외, 상관관계와 인과관계의 구분 |
| 영상으로 전달할 수 있는가 | 발화의 전달력, 실제 반응, 언급한 사진·물체, 세로 구도 확인 필요성 |

후보의 우선순위는 목적 적합성과 독립적인 이해 가능성에 대한 편집 판단이다. 측정하지
않은 조회수·바이럴 확률·전환율을 예측값으로 제시하지 않는다.

## 3. 화자보다 대화의 의미를 기준으로 발췌한다

1. 대본 전체의 흐름에서 후보를 찾고, 그 질문의 답변이 끝나거나 주제가 바뀌는 곳까지
   읽는다. 후보 밖의 뒤 설명에서 핵심 답이 나오는지 확인한다. 고정된 몇 초의 문맥만
   보거나 마지막 문장이 종결형이라는 이유로 읽기를 멈추지 않는다. 중심 화자의 문장만 필터링해
   고르지 않는다. 질문, 되물음, 함께 완성하는 문장이 뜻이나 자연스러움을 살리면 남긴다.
   화자 비중이나 화면에 보여줄 인물에 대한 사용자 요청이 있으면 이를 따르되, 필요한
   맥락은 허용된 질문 음성·설명 문구 등으로 보존한다.
2. 각 후보가 약속하는 질문, 원문에 있는 답, 그 답을 이해하는 데 필요한 설명과
   마무리를 먼저 적고 각 근거를 원문에 연결한다. 도움의 의미나 역할 설명을 약속한
   정보형에서 ‘누가 돕나 → 의료진’처럼 대상만 밝히고 약속한 설명을 잘라내면
   미완성으로 판정한다. 모든 단순한 질문에 추가 설명을 강제하는 규칙은 아니다.
   길이에 맞지 않으면 반복을 줄이거나 질문의 범위를 좁히거나 더 긴 후보로 제안한다.
   핵심 답변을 자르는 방식으로 짧게 만들지 않는다. 예열 대화나 반복은 줄일 수 있지만,
   필요한 조건을 빼서 더 강한 주장으로 만들지 않는다. 꼭 필요한 배경 설명은 편집 문구로
   표시하고 실제 발언처럼 따옴표로 만들지 않는다.
3. 떨어진 구간을 연결할 때는 각 범위를 분리해 기록한다. 시간 순서를 기본으로 삼고,
   재배열한다면 이유와 의미 보존을 설명한다. 다른 순간의 반응을 이어 붙여 원래 그 말에
   반응한 것처럼 만들지 않는다.
4. 같은 이야기의 다른 컷은 `alternate_of` 등으로 연결한다. 독립 주제처럼 중복 집계하지
   않는다. 개수나 길이를 채우기 위해 완결성이 낮은 후보를 넣지 않는다.
5. 제목과 첫 화면 문구를 제안하되 실제 발언, 체험, 성과보다 강하게 쓰지 않는다.
   대본만 봤다면 웃음·표정·몸짓이나 전달력을 확인했다고 쓰지 않는다.

정보형은 **질문 → 답과 설명 → 시청자가 가져갈 결론 → 선택적인 추가 시청 안내**로
완결성을 확인한다. ‘전체 영상에서 확인하세요’는 이미 전달한 답을 확장하는 안내이며,
답변 중단을 정당화하는 장치가 아니다. CTA는 편집 문구로 구분하고, 실제 발언이나
출처에 없는 결론을 만들어 넣지 않는다. 연결할 영상과 그 안의 추가 내용을 특정하며,
플랫폼의 실제 연결 기능을 제안할 때만 해당 기능·채널 조건을 확인한다.

건강·금융·법률 등 정확성이 중요한 주장이 후보의 핵심이면 해당 분야의 원문 근거와
대조한다. 출처 미상 연구, 지침과 충돌하는 단정, 사례의 조건을 빼야만 성립하는 편집은
우선 후보와 분리하고 **무엇을 확인해야 재평가할 수 있는지** 적는다. 단순한 경험담이나
관련 없는 후보까지 일괄 보류하지 않는다.

## 4. 원문과 시간 범위를 추적 가능하게 남긴다

결과를 정리하기 전에 [후보 기록과 검증 기준](references/candidate-contract.md)을 읽는다.
기존 프로젝트 형식이 있으면 그 형식에 필요한 정보를 보강한다.

- 원문 단어·화자·토큰 또는 대본 발화 ID와 사용한 리비전을 연결한다. 교정본을 그대로
  발췌하고 새로운 교정은 별도 이력으로 남긴다. 원본 파일을 직접 덮어쓰지 않는다.
- 음성 단어 앵커와 자막 표시 시간을 구별한다. 표시 시간만 있으면 탐색용 범위로 쓰고
  정확한 음성 컷으로 제시하지 않는다. 없는 음성 앵커나 화자를 추정해 채우지 않는다.
- 발췌 범위의 길이는 같은 원본 타임라인의 `end − start`로 계산하고, 여러 구간이면
  합산한다. 누락된 발화, 공유 앵커, 중첩은 숨기지 않는다. 합계는 최종 영상 길이가 아니다.
- 화자 확인, 컷 경계 청취, 화면 속 인물 확인, 자막 검증을 별도로 기록한다. 후보 선정
  단계에서 하지 않은 검수를 완료로 표시하지 않는다.
- 설명 완결성 검수도 별도로 남긴다. 약속한 질문에 실제로 답하는지, 선택 구간 이후에
  빠뜨린 답·조건이 없는지, 왜 그 지점에서 끝나는지 원문으로 설명할 수 있어야 한다.
  단어 보존·파형 일치·자막 프레임 검사 통과는 이 의미 검수를 대신하지 않는다.
- 사용자 화자 교정은 해당 단어부터 적용하고 근거와 리비전을 남긴다. 같은 ASR 앵커에
  연결된 인접 단어까지 같은 화자라고 바꾸거나, 화자 결정으로 정밀 발화 시간이
  확정됐다고 간주하지 않는다.

길이 계산과 연결 컷의 실제 예가 필요하면
[적용 사례](references/worked-example.md)를 읽는다. 사례의 인물·분야·개수·길이는
방법을 설명하는 예이며 다음 작업의 고정 조건이 아니다.

## 5. 선택할 수 있는 결과로 전달한다

요청에 맞는 분량의 후보 표를 먼저 제시한다. 후보별로 제목 제안, 원본 구간, 계산 가능한
선택 범위 길이, 선정 이유를 담고, 우선 제작할 소수의 서로 다른 후보를 추천한다.
발췌 대사와 흐름, 꼭 남길 문맥, 피할 해석, 남은 검수는 상세 기록에 연결한다.

저장소에서 재사용하거나 후속 편집에 넘길 작업이면 기존 산출물 위치에 읽기용 선정안과
기계가 읽을 수 있는 후보 기록을 남긴다. 채팅에서 몇 가지 아이디어만 원하는 요청에
여러 파일 형식을 강제하지 않는다.

전달 전 원문 인용과 화자, 범위 합계, 중복 주제, 출처 링크와 근거의 강도를 확인한다.
후속 제작에서는 실제 오디오와 화면으로 컷을 확정하고 프로젝트의 자막·렌더링 검증을
따르도록 인계한다. 발췌 요청을 전체 영상 제작이나 업로드로 확대하지 않는다.
